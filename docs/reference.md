# Reference

## Architecture

- `capsule/server/`: Lakebed schema, authenticated queries/mutations, upload endpoint.
- `capsule/client/`: Preact dashboard and responsive styles.
- `capsule/shared/`: pure validation, compact encoding, and accounting.
- `collector/`: local Node 24 SQLite outbox, incremental JSONL scanner, Git/jj identity, CLI.
- `extension/`: Pi lifecycle integration; no daemon or resources opened just by loading it.
- `shared/usage.js`: collector-only Pi normalization and stable source-entry IDs.

The hosted app has no Node HTTP server, SQLite, Docker, NixOS service, SSH target, or reverse proxy. Lakebed manages persistence, transport, HTTPS, and sign-in. The collector still uses Node built-ins locally; it does not depend on Lakebed's client SDK.

## Access and credentials

Lakebed developer login supports GitHub, but app sign-in currently supports **Google only**. The first owner must present both a verified Lakebed sign-in and a random one-time setup key. An existing owner cannot be replaced through the app. The key stays in `capsule/.env.lakebed.server`; the private local copy is `.local/owner-setup-key`. Once bound, remove `OWNER_SETUP_KEY` from the env and redeploy if desired. Recreating server secrets does not replace stored ownership.

All dashboard reads and settings mutations enforce the stored account's stable `userId`, not its email or display name. The app-wide sign-in policy stays off so collectors can reach the upload endpoint. Guests cannot read usage or settings. Built-in sign-in handles session verification; there is no custom OAuth cookie or CSRF implementation.

Collectors authenticate only `POST /api/ingest` with `Authorization: Bearer slop_...`. That credential is not a Lakebed browser identity and cannot call dashboard operations. Each credential binds to its first machine UUID, is SHA-256 hashed at rest, and can be revoked. The bootstrap machine credential is generated by `npm run setup`; its local plaintext copy is `.local/upload-token`. A revoked bootstrap token stays revoked even while the env contains it.

The public shell and `GET /api/health` contain no private usage. Hosted database inspection is private; do not deploy with `--public-inspect`.

## Free-plan operation

An owned deployment does not expire. Lakebed provides a free `*.lakebed.app` hostname; custom domains require a paid plan. The generated `capsule/lakebed.json` binds only your local checkout to your deployment and is ignored by version control. A fresh clone must generate its own secrets and deployment; never copy another user's deployment binding.

Current limits: 1 MiB state, 16,384 rows, 10,000 requests/day, 1,000 mutations/day. A handler returns at most 1,000 rows, reads at most 5,000 rows, performs at most 100 index scans and 1,000 writes. Limits can change; inspect current usage with `npm run inspect -- --usage` and consult https://docs.lakebed.dev/limits/.

Uploads contain at most **40 records**. Idle collectors send nothing unless their authentication-type profile changes; each changed profile uses one mutation. Every batch is a Lakebed transaction; a quota failure rolls back the complete batch. Collectors retain acknowledged and pending metadata locally. Daily `Retry-After` is honored across collector restarts. Stored quotas have no daily reset; export and deliberately redesign/archive/upgrade before they fill. The app does not delete rows, discard deduplication keys, or turn unknown usage into zero to fit the free tier.

Events use positional JSON to reduce state overhead. The dashboard paginates reads in 200-record pages and computes filters and totals locally over all hosted records. It labels partially loaded totals and disables export until all records arrive. Settings show packed payload characters, not an authoritative total byte count; use CLI inspection for actual state bytes. Large backfills or several continuously active machines can exhaust free limits. This is not unlimited analytics storage.

## Collection

Install the repository as a local Pi package. Collection begins at session start, records completed model usage including ephemeral sessions, periodically scans changed persisted sessions (including children), and attempts a bounded final upload at shutdown. While Pi is closed, there are no periodic uploads. CLI `sync` or `import` can run without launching Pi.

Config defaults to `~/.config/slop-statistics/collector.json` (0600); local state is `~/.local/state/slop-statistics/collector.sqlite`. Override with `SLOP_CONFIG`. The default session directory is `~/.pi/agent/sessions`; `sessionsDir` or `PI_CODING_AGENT_SESSION_DIR` overrides it. Config and queue belong to one stable machine UUID. Do not share SQLite over a network filesystem or copy an initialized config between computers.

Historical import is optional and best-effort. It deduplicates, tolerates unreadable/malformed files, and checkpoints only complete UTF-8 JSONL lines. Missing files cannot be recovered. It may exceed free hosted storage: prefer new usage unless you have checked the size.

## Billing and pricing

The dashboard uses one money figure: **estimated usage value**, the USD valuation of all usage at API rates, including subscriptions and unclassified records. It is not a bill. Project/model/machine/session comparisons always show tokens and this same value; the money toggle ranks them by value and switches the timeline to USD. Billing labels do not affect valuation unless you explicitly filter by them. Missing prices remain unknown; partial totals sum only known prices.

Billing classification is optional secondary metadata, configured in Settings. Actual subscription fees are manually entered there and account-wide; they are separate from usage value and not allocated to repositories, models, or machines.

The collector infers billing from stored Pi credential **types**: OAuth becomes subscription-equivalent; API keys become API usage. It never uploads keys/tokens or resolves secret commands. Each machine uploads its own bounded defaults, also used for its unclassified historical records without reimport or changing stored prices. Settings displays these defaults. New records retain their classification; explicit collector rules (including unknown) and dashboard rules take precedence.

Detection reads `<PI_CODING_AGENT_DIR or ~/.pi/agent>/auth.json`; collector `authFile` can override that path. Profiles refresh at sync and survive unreadable/malformed auth files. This is an inference, not proof of past billing: use explicit rules for history collected under different credentials, environment/custom credentials, or flat-rate plans that use API keys. Dashboard provider/model rules apply retroactively; exact-model rules win. For the same model billed differently on different machines, set each collector's `billingRules` and avoid a global override. Rules change classification, not prices.

Pi's recorded cost is preserved. A zero catalog price with nonzero tokens means unpriced, not free. Optional collector `prices` take four nonnegative USD-per-million rates (`input`, `output`, `cacheRead`, `cacheWrite`) for a provider/model and apply only to newly collected events. Stored usage and prices are immutable; classification rules/defaults can change their presentation. Reasoning is already included in output; cache tokens are disjoint from uncached input. Unknown counts/costs are counted explicitly, not inferred from the selected model. Missing external extension calls cannot be reconstructed.

The overview shows exact regular-input, cache-read, cache-write and output counts, a category-stacked timeline, and a per-model table. Cache-read share is `cacheRead / (input + cacheRead + cacheWrite)`: a token-weighted input share, not a request hit rate. Output is excluded. Records missing any input category are excluded from that ratio and explicitly counted; category totals include known values only. Filters apply to the complete breakdown. The unified value card and comparison tables include known prices on unclassified records too; they do not require billing configuration.

## Identity and privacy

Repository identity prefers origin, then another remote. SSH and HTTPS normalize without credentials, fragments or `.git`. Git linked worktrees share storage; jj workspaces share the repository. Local-only repositories are machine-scoped, not checkout-scoped. Client `projectAliases` or dashboard aliases can group missing/renamed checkouts and different remotes.

Usage IDs depend on source entry identity, timestamp, kind, provider/model and token counts—not the new machine, checkout or session. Copies/forks therefore do not double-charge. First ingestion owns attribution. Id-less legacy entries have weaker deduplication. Stored metadata is explicitly allowlisted; prompts, tool output, credentials and raw checkout paths are excluded. Repository/model names can still be sensitive. Titles are disabled unless `sendSessionTitles: true`.

## Verification and recovery

`npm test` runs usage/VCS tests and real Lakebed in-memory transaction tests for ownership, upload-only credentials, revocation, validation, deduplication, rollback, pagination, accounting and collector retries. `npm run check` type-checks the capsule and extension; `npm run build` enforces Lakebed's capsule restrictions. `npm run test:browser` checks the Preact dashboard using a test identity/transport adapter backed by the same real capsule handlers; it does not test Google's external sign-in service.

Install a browser for UI checks with `npx playwright install chromium`. On NixOS, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to a Nix-provided Chromium headless shell instead of downloading an unpatched executable.

`npm run screenshot` regenerates `docs/screenshot.png` using synthetic in-memory data and the real dashboard. It never reads collector configuration, opens a hosted account, or uploads usage.

Export metadata in the dashboard, or privately run `cd capsule && npx lakebed db export <deploy-id> --out /private/path/backup.json`. Protect exports and local databases like live usage. Back up local SQLite with its online backup API, not by copying only the main file while WAL writes are active. To replay acknowledged records after disaster recovery, stop collectors, back up their databases, set `sent=0` locally, and sync. Hosted IDs deduplicate replay. Retain config, machine UUID and queue together.

The Pi development type dependency currently carries a shrinkwrapped `brace-expansion` advisory; it is not included in the deployed artifact. Root overrides cannot replace that dependency. Revisit when Pi publishes a patched version.
